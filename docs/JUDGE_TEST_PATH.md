# Judge Test Path

## Fast path: under two minutes

```bash
npm install
npm run validate
npm start
```

Open <http://127.0.0.1:4173>.

1. Click **Analyze change**.
2. Confirm the direct rename is `BLOCKED` with score 80.
3. Confirm the Local AI Copilot panel appears and honestly reports `NOT_ENABLED` in the default fixture flow unless the local AI runtime was explicitly enabled.
4. Confirm five downstream assets and their paths are visible in the fixture analysis.
5. Confirm PII, breaking lineage, and fixture query-evidence findings.
6. Confirm five generated review files — dbt model, schema tests, rename parity data test, rollback SQL, and impacted-owner brief — and inspect the manifest-linked sandbox evidence and reviewer-ready PR packet regenerated by `npm run validate`. The PR packet is a delivery handoff, not one of the five generated artifact files.
7. Click **Approve safe scope**.
8. Confirm a `csp_...` passport and manifest hash appear.
9. Click **Prepare write-back**.
10. Confirm fixture mode reports that operations were prepared but no catalog was modified.

## What this proves

- End-to-end application behavior
- Visible non-authoritative AI layer with honest fallback
- Deterministic policy and fixture-backed graph traversal
- Safe alternative generation
- Manifest-linked local sandbox conformance and reviewer-ready PR delivery preparation
- Approval/passport boundary
- Mutation gating and honest fixture labeling
- Executable local conformance proof for the generated artifact bundle via `npm run sandbox`

## What it does not prove

- Live DataHub connectivity
- A local-model-backed `PASS` explanation unless Ollama is installed and enabled
- Live metadata mutation
- Warehouse execution
- A created, reviewed, or merged GitHub PR
- Production readiness

The separate live path is documented in [LIVE_DATAHUB_SETUP.md](LIVE_DATAHUB_SETUP.md).

## Local default AI state vs hosted Pages behavior

- The local default fixture flow keeps the AI layer `NOT_ENABLED` unless Ollama is installed and explicitly enabled; only then can a local-model-backed `PASS` explanation appear.
- The hosted GitHub Pages demo replays the committed `RECORDED LOCAL OLLAMA PROOF` artifact (`examples/outputs/proofs/ollama-ai-proof.json`). It is a recorded local capture, not hosted live inference, and the page labels it that way.

## Pre-recorded local DataHub proof

- `examples/outputs/live-datahub-read-evidence.json` preserves the five bounded read-only MCP tool types, including the saved query-read result and exact lineage-path reads for discovered downstream endpoints.
- `examples/outputs/live-datahub-writeback-evidence.json` is a recorded `PASS` export from source commit `baa61387324868b39427030c447b94c2b9599c03`: it preserves three `APPLIED` receipts, a same-passport retry with three `SKIPPED` receipts, and exact-one durable read-back results.
- Both artifacts are synthetic-local, never production evidence. No new final-SHA DataHub capture is required: this historical disposable-local evidence remains valid while `npm run evidence:check` passes on the submitted commit.
- Production warehouse execution remains `NOT_RUN` and is not claimed anywhere in the judge path.
